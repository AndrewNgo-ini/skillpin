The model

One skill, several places it is available

A skill is canonical. A pin is a location where that skill is available. SkillPin lists the skill once and shows its pins underneath, instead of showing you the same skill four times because it sits in four directories.

research
~/.agents/skills/ Shared
~/.claude/skills/ Claude
./.agents/skills/ Project moonfish
Shared is the default target
Agents that follow the shared .agents/skills convention all read it, so one copy covers them.
Per-agent formats stay out of the way
.claude, .codex and .hermes are there when you need them, hidden behind "More formats" when you don't.
Project pins copy into the repository
The repository stays portable and can commit the skills it depends on, instead of relying on what happens to be on your machine.
Shared skills say where they came from
Read from ~/.agents/.skill-lock.json: the GitHub repository a skill was installed from, or Local / untracked.

Discovery

It finds your agents, you don’t list them

SkillPin carries no list of supported agents. It looks in your home folder for any dot-directory holding a skills folder, parses each SKILL.md for its name and description, and groups the results by skill name. An agent it has never heard of appears without a new release. The same rule runs inside every project folder you add.

Found on diskShown as
~/.agents/skills/Shared
~/.claude/skills/Claude
~/.cursor/skills/Cursor
~/.hermes/profiles/<name>/skills/Hermes <name>
<project>/.codex/skills/<project>: Codex
~/.whatever/skills/Whatever

Thirteen agents are recognised by name and given their own badge icon — Shared, Claude, Codex, Cursor, Copilot, Gemini, Kimi, Grok, OpenCode, Cline, Goose, Hermes and Pencil. Everything else is listed under its capitalised directory name.

Install

Build it in under a minute

macOS 14 or later, Swift 6. There are no external dependencies, and there is no signed release yet, so you build it yourself. 

git clone https://github.com/AndrewNgo-ini/skillpin.git
cd skillpin
./Scripts/package-app.sh     # builds dist/SkillPin.app
open dist/SkillPin.app

swift run SkillPin           # or run it straight from the terminal

v0.1.0

Reading, searching, filtering and project scanning work today. Writing a pin from the app does not: the pin sheet builds the destination path and shows it to you, but it does not copy the skill there yet.

Signed builds and a Homebrew cask come after that. If you want a say in the pin model before it is settled, now is the time to open an issue.
